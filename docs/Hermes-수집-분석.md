# Hermes 수집량 분석과 16개 병렬 판정

2026-09-10 조사. 기존 100개 레포에서 수집한 로컬 결과를 분석했다.
원본: `.radar-web/run-2ae39c3a5b2f4bc29e0729444a33b233/issues.jsonl`.
원본의 파일 수정 시각은 2026-09-10 07:47:15 UTC이며 Git에는 포함하지 않는다.

Hermes의 열린 이슈 전체 13,813개라는 이전 선정 수치와 실제 판정 대상 1,527개는 다른 수치다.
Hermes가 가장 큰 비중은 아니었으며 Codex와 합치면 4,086건, 전체의 57.0%였다.
Hermes 1,527건의 이슈 번호는 모두 고유하고 작성자는 1,170명이다. 같은 번호를 중복 수집한 결과는 아니다.

## 왜 많이 들어왔나

1. **신규 이슈 자체가 많다.** 저장된 Hermes 이슈 중 937건(61.4%)이 2026-09-03 00:00 UTC 이후 생성됐다.
2. **오래된 이슈의 최근 갱신도 수집한다.** 나머지 590건(38.6%)은 그 이전에 생성됐고, 가장 오래된 생성일은 2026-03-06이다.
   이 날짜 구분은 생성일 분포를 설명하기 위한 기준이다. 기존 실행의 정확한 `since` 시각은 결과 파일에 저장되지 않아 그대로 재현할 수는 없다.
3. **페이지당 100개는 전체 상한이 아니다.** `radar.collect`는 `state=open`, `since`, `per_page=100`으로 요청하고 `--paginate --slurp`로 모든 페이지를 읽는다.
   PR·담당자 있음·봇 작성 이슈만 제외하며, 라벨이나 레포별 건수로 제한하지 않는다.

GitHub의 `since`는 마지막 갱신 시각 기준이다. 따라서 최근에 만들어진 이슈만 의미하지 않는다.
근거: [GitHub List repository issues](https://docs.github.com/en/rest/issues/issues#list-repository-issues), [수집 코드](../radar.py).

오래된 이슈의 최근 활동도 API로 확인했다.
[Hermes #466](https://github.com/NousResearch/hermes-agent/issues/466)은 3월 6일 생성됐지만 9월 5일 `tool/file` 라벨 추가 이벤트가 있고,
[Hermes #1855](https://github.com/NousResearch/hermes-agent/issues/1855)는 3월 18일 생성됐지만 9월 6일 `comp/tools` 라벨 추가 이벤트가 있다.
조회 경로는 `repos/NousResearch/hermes-agent/issues/{number}/events`다.
이 사례는 오래된 이슈에 최근 활동이 있음을 보여주며, 590건 전체가 라벨 변경 때문에 포함됐다는 뜻은 아니다.

추가로 `state=open&since=2026-09-03T00:00:00Z&per_page=100`을 전체 페이지 조회했다.
6,215건 중 PR 4,583건, 담당자 있음 1건, 봇 작성 10건을 순서대로 제외하면 1,621건이었다.
이는 기존 수집 후 다시 조회한 값으로, 시점과 정확한 `since` 차이 때문에 저장된 1,527건과 다르다.
저장된 1,527건은 재조회 결과에서 모두 확인됐고, 그중 오래된 590건 모두 `updated_at`이 9월 3일 이후였다.

저장된 라벨 기준으로 `type/bug` 1,015건, `type/feature` 422건이다. 라벨은 중복될 수 있다.
스팸이나 자동 생성 이슈의 비율은 확인하지 않았다. 작성자 수와 라벨만으로 정상·스팸을 단정하지 않는다.

## 처리 속도 변경

판정은 이슈당 `codex exec`를 한 번 실행한다. 기존 최대 4개 동시 실행과 제출 버퍼를 모두 16개로 늘렸다.
웹도 같은 CLI를 실행하므로 다음 판정부터 적용된다. 기본 모델은 `gpt-5.6-luna`, 추론은 `low`다.
테스트는 모델 호출을 대체한 32건을 처리하면서 실제 동시 진입 16개와 결과 32건 보존을 확인한다.
실제 모델의 처리 시간과 실패율은 이번 변경에서 실측하지 않았으며, 4배 속도 향상을 보장하지 않는다.
현재 기본 30개 목록과 Hermes 제외 상태는 유지한다.

동시 실행 수는 사용량 상한이 아니다. 건수 제한 없이 1,527건을 판정하면 동시 실행을 늘려도 모델 호출은 1,527회다.
레포 선택 범위를 유지하면서 호출량을 제한하려면 판정 단계의 실행당 총량과 레포별 상한을 별도로 정해야 한다.
현 구현은 판정 시작 버튼만 분리돼 있고 이 상한은 아직 없다.
