# 미구현 기능 통합 진행 상태

확인일: 2026-10-23. 구현 브랜치는 `codex/feature-integration`이다.
Vercel의 DB 연결과 실제 GitHub 로그인은 확인했다. Windows DB 설정과 개인 구독 저장·재조회도 확인했다. 실제 공용 배치는 Vertex AI 429로 실패해 전체 목표는 아직 완료되지 않았다.

## 현재 제품 범위

2026-10-23 사용자 결정으로 알림과 저장소 구독 개인화에 집중한다. 개인 기여 기록은 현재 제품 구현·운영 완료 목록에서 제외하고 화면 진입점과 브라우저 마운트를 제거한다. 내부 모듈·API·테스트와 기존 저장 데이터는 보존한다.

공용 배치는 동시 판정 기본값을 16개에서 4개로 낮추고 `community_batch.py --workers 1-16`으로 조정한다. 판정 기준, 실행당 100건·레포당 20건 상한과 실패 시 이전 snapshot 보존은 유지한다. 429는 요청 한도 또는 처리 용량 부족이며 현재 진단만으로 둘을 구분하지 못한다.

## 배포와 실사용 증거

2026-10-23 사용자가 환경변수 설정 후 새 Production 배포를 완료했다.
정식 주소 `https://repobite.vercel.app`의 배포 ID가
`dpl_3hM75bhpM9QCwDeDrYt22WZgwjJv`임을 `vercel inspect`로 확인했다. 생성 시각은 11:06:13 한국시간이고 상태는 Ready다.
일반 HTTPS 요청으로 HTML, data.json, 두 UI 모듈이 200이며 로컬 파일과 SHA-256이 일치했다.
SSO 우회 요청을 사용하지 않았다. 기존 data.json은 재판정하거나 새 결과로 덮어쓰지 않았다.

- 익명 세션 조회는 200과 `authenticated:false`를 반환했다.
- 공용 목록 조회는 200이다. 공용 등록은 0개이고 배치 snapshot은 아직 없다.
- 로그인 시작은 302로 GitHub 인증 화면에 연결된다. DB의 임시 OAuth 상태 저장, PKCE S256, 정식 callback 주소와 Secure/HttpOnly 쿠키를 확인했다.
- 사용자가 브라우저에서 GitHub 로그인을 완료했고 정식 주소의 `auth=success`, 계정 표시, 개인 구독 목록과 개인 기여 목록 조회를 확인했다. 이는 실제 OAuth 왕복과 계정·세션의 DB 저장 증거다.
- 익명 기여 기록 조회는 401이었다.
- 로그인 상태가 새로고침 뒤에도 유지됐다. 개인 구독에 기본 저장소 `withastro/astro`를 저장하고 새로고침 후 재조회했으며, 해지 후 원래 빈 목록으로 복원했다. 알림 이메일과 수신 동의는 변경하지 않았다.
- 기본 저장소의 공개 등록 요청은 200과 `created:false`, `default:true`였다. 공용 등록 목록에 중복을 추가하지 않았다.
- 운영 브라우저 390px 폭에서 공개 저장소 선택, 이슈 열기, 착수의 로그인 안내를 확인했다.
- 로그인한 계정의 착수·취소·재개·PR 연결은 모의 API 브라우저 검사다. 실제 기여 기록 변경·PR 연결의 운영 검증은 아직 하지 않았다.

## 검증과 운영 차이

Mac Python 3.14의 12개 회귀 묶음, Node 계정·기여 UI 47건과 공개 화면 검사가 통과했다.
Windows 임시 소스 폴더에서 Python 12개 회귀 묶음과 PowerShell 검사가 통과했다.
첫 검사에서 신규 테스트 2개가 UTF-8 결과를 CP949로 읽어 실패했고, 읽기 인코딩을 명시한 뒤
해당 2개를 다시 실행해 통과했다. 운영 체크아웃이나 작업 스케줄러는 변경하지 않았다.
Windows에는 Node가 없어 Node 검사는 Mac 결과만 있다. CI에는 Node 24 검사를 설정했으며
해당 통합 커밋의 원격 CI 실행은 아직 없다.
2026-10-23 Windows 운영 체크아웃을 `codex/feature-integration`의 구현 커밋 `b32c718`로 전환했다.
기존 운영 수정 3건은 range-diff에서 통합 브랜치의 대응 커밋과 동일함을 확인했다.
기존 운영 브랜치와 수집 데이터를 보존하고 실제 운영 폴더에서 Python 회귀 12개 묶음과 PowerShell 검사가 통과했다.
웹 작업을 재시작하고 웹·상태 서버·계정 세션·두 UI 모듈의 HTTP 200과 새 모듈 파일 일치를 확인했다.
실제 정기 배치 성공과 다음 부팅 복구는 미검증이다.
웹 작업은 재확인 시 `Running`, 실행 제한은 여전히 `PT72H`, 배치의 최근 종료 코드는 1이었다.
기존 웹 작업의 영구 제한 수정은 서버 콘솔에서 암호 보안 입력이 필요하다.
절차는 [Windows 운영](Windows-운영.md)에 있다.

## 외부 설정 후 확인할 흐름

비밀값은 채팅이나 소스에 넣지 않는다. [계정·구독·수동 발송](계정-구독-수동발송.md)의
이름과 callback 주소로 기존 OAuth App과 새로 생성한 Upstash DB를 연결한다.
Vercel에는 OAuth 두 값과 DB 두 값, Windows 배치 계정에는 같은 DB 두 값을 설정한다.
Vercel 설정과 재배포는 완료했다. Vercel Production Secret은 CLI로 다시 내려받지 못해 자동 전달하지 않았다. 사용자가 Mac의 숨김 입력 도구에 DB 두 값을 입력해 SSH로 Windows User 환경변수에 등록했다. 비밀값은 채팅·명령 인자·파일에 기록하지 않았다.
홈서버에서 DB 읽기와 로그인 계정 저장을 확인하고 11:18:25 한국시간에 기존 예약 작업으로 공용 배치를 수동 실행했다.
주간 Trending 14개와 유명 저장소 15개를 발굴하고 기본 목록과 합친 57개 저장소에서 이슈 1,782건을 수집했다. 새 판정 100건 중 85건 성공, 15건은 각각 5회 HTTP 시도 후 `429 RESOURCE_EXHAUSTED`로 실패했다.
11:24:51 결과 파일이 저장됐고 작업 종료 코드는 1이다. snapshot을 쓰지 않았으며 Windows DB와 정식 운영 API에서 snapshot이 없음을 확인했다. 정기 트리거의 성공과 공개 결과 반영은 미검증이다.

설정 완료 후 실제 GitHub 로그인, 개인 저장소 구독·이메일 수신 동의 저장과 재조회를 확인한다.
Windows 통합 코드 전달은 완료했다. DB 설정 후 공용 등록 -> 수집 대기 -> 배치 종료 0 -> 같은 DB 공개 결과를 확인한다.
그 다음 운영자가 초안을 생성하고 직접 보낸 메일만 확인·동기화한다.
11시 발송은 확정된 예약이 아니며 자동 이메일 송신은 구현하지 않았다.

## 남은 설계 경계

사용자 확정에 따라 비공개 전환과 저장소 HTTP 404는 해당 레포만 이번 수집에서 제외한다.
등록·구독을 보존하고 다음 실행에서 다시 확인한다. 새 공개 결과에는 제외 레포의 과거 이슈와
발굴 목록도 포함하지 않는다. 전부 제외된 경우에는 판정하지 않고 빈 공개 결과를 저장한다.
GitHub 인증 실패·장애·요청 제한·시간 초과·응답 형식 오류는 전체 실패로 처리하며 이전 공개 결과를 유지한다.
공개 응답과 실제 HTTP 404의 구분을 Mac의 실제 GitHub 조회로 확인했고,
저장소별 제외·공개 복귀·전체 제외·장애 시 보존은 외부 호출 없는 회귀 검사로 확인했다.
이 후속 수정의 `test_radar.py`, `test_community.py`는 Mac과 Windows 임시 폴더에서 통과했다.
발굴·품질 평가 도구의 Mac 회귀 검사도 통과했다. 2026-10-23 Windows 운영 체크아웃에도 반영했다.

`web.Application`이 상태·프로세스·파일 저장을 함께 담당하는 단일 책임 원칙 위반이 남아 있다.
공개 변환은 `public_feed.py`로 분리했으며 배치가 웹 서버 모듈에 의존하지 않는다.
이메일 소유권 확인은 없고 운영자 발송 확인은 제공자 전송 성공·수신 도착 증거가 아니다.
