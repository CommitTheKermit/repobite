## 배포와 실사용 증거

구현 커밋 `51d3b26`을 Vercel 운영 환경에 배포했다.
정식 주소 `https://repobite.vercel.app`의 배포 ID가
`dpl_FgNtFoiWhoQUHkLVwJNzUqLduRJW`임을 `vercel inspect`로 확인했다.
일반 HTTPS 요청으로 HTML, data.json, 두 UI 모듈이 200이며 로컬 파일과 SHA-256이 일치했다.
SSO 우회 요청을 사용하지 않았다. 기존 data.json은 재판정하거나 새 결과로 덮어쓰지 않았다.

- 익명 세션 조회는 200과 `authenticated:false`를 반환했다.
- 로그인 시작과 공용 목록 조회는 비밀 설정 미입력 상태에서 503이었다.
- 익명 기여 기록 조회는 401이었다.
- 운영 브라우저 390px 폭에서 공개 저장소 선택, 이슈 열기, 착수의 로그인 안내를 확인했다.
- 로그인한 계정의 착수·취소·재개·PR 연결은 모의 API 브라우저 검사다. 실제 OAuth와 DB 저장의 증거가 아니다.

## 검증과 운영 차이

Mac Python 3.14의 12개 회귀 묶음, Node 계정·기여 UI 47건과 공개 화면 검사가 통과했다.
Windows 임시 소스 폴더에서 Python 12개 회귀 묶음과 PowerShell 검사가 통과했다.
첫 검사에서 신규 테스트 2개가 UTF-8 결과를 CP949로 읽어 실패했고, 읽기 인코딩을 명시한 뒤
해당 2개를 다시 실행해 통과했다. 운영 체크아웃이나 작업 스케줄러는 변경하지 않았다.
Windows에는 Node가 없어 Node 검사는 Mac 결과만 있다. CI에는 Node 24 검사를 설정했으며
해당 통합 커밋의 원격 CI 실행은 아직 없다.
현재 Windows 운영 코드는 기존 운영 수정 커밋 `cffe3dd`이며 새 기능 통합 버전으로 바꾸지 않았다.
실제 정기 배치 성공과 다음 부팅 복구는 미검증이다.
웹 작업은 재확인 시 `Running`, 실행 제한은 여전히 `PT72H`, 배치의 최근 종료 코드는 1이었다.
기존 웹 작업의 영구 제한 수정은 서버 콘솔에서 암호 보안 입력이 필요하다.
절차는 [Windows 운영](Windows-운영.md)에 있다.

## 외부 설정 후 확인할 흐름

비밀값은 채팅이나 소스에 넣지 않는다. [계정·구독·수동 발송](계정-구독-수동발송.md)의
이름과 callback 주소로 기존 OAuth App과 Upstash DB를 연결한다.
Vercel에는 OAuth 두 값과 DB 두 값, Windows 배치 계정에는 같은 DB 두 값을 설정한다.
Vercel 설정 입력 후에는 새 운영 배포가 필요하다.

설정 완료 후 실제 GitHub 로그인, 개인 저장소 구독·이메일 수신 동의 저장과 재조회를 확인한다.
Windows에 통합 코드를 전달하고 공용 등록 -> 수집 대기 -> 배치 종료 0 -> 같은 DB 공개 결과를 확인한다.
그 다음 운영자가 초안을 생성하고 직접 보낸 메일만 확인·동기화한다.
11시 발송은 확정된 예약이 아니며 자동 이메일 송신은 구현하지 않았다.

## 남은 설계 경계

현재 배치는 기존 등록 저장소 하나가 비공개 전환되거나 삭제되면 전체 실패한다.
이전 공개 결과는 보존하지만 해당 등록을 제거하는 API가 없어 반복 중단될 수 있다.
해당 저장소만 제외할지 기존 중단 정책을 유지할지는 사용자에게 확인 중이다.
GitHub 장애나 요청 제한을 정상적인 빈 결과로 바꾸어 공개하지 않는다.

`web.Application`이 상태·프로세스·파일 저장을 함께 담당하는 단일 책임 원칙 위반이 남아 있다.
공개 변환은 `public_feed.py`로 분리했으며 배치가 웹 서버 모듈에 의존하지 않는다.
이메일 소유권 확인은 없고 운영자 발송 확인은 제공자 전송 성공·수신 도착 증거가 아니다.
