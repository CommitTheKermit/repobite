# 레포 카테고리 매핑

작성일: 2026-09-14

## 목적

정적 시안의 상단 레포 필터와 이후 탐색용 분류의 기준이다. 이슈의 내용이나 GitHub 라벨을 분류하지 않는다. 레포는 서로 다른 탐색 의도를 가질 수 있어 카테고리를 최대 두 개까지 가진다.

현재 원본은 `prototypes/layers.html`의 `article[data-categories]`다. 분류 근거는 [수집 레포 시각 자산 조사](수집-레포-시각자산-조사.md)의 프로젝트 설명이다.

## 카테고리 사전

| 상위 필터 | 세부 카테고리 |
| --- | --- |
| AI | AI·ML, 에이전트·자동화 |
| 프레임워크 | 웹 프레임워크, UI·디자인 시스템, 백엔드·API |
| 데이터 | 데이터베이스, 검색·지식 |
| 개발 도구 | 개발 도구, IDE·터미널, 테스트·품질, CI/CD·릴리스 |
| 인프라 | 인프라·클라우드, 관측성, 네트워크·시스템 |
| 보안 | 보안·인증 |
| 앱 | 데스크톱 앱, 모바일, 생산성 |
| 미디어 | 미디어·크리에이티브, 게임·그래픽 |

세부 카테고리는 현재 표본에 없는 경우에도 새 레포를 받기 위한 사전으로 유지한다. 상단 칩은 세부 카테고리를 묶는 상위 필터이며, 나중에 구현할 때 `data-filter`의 공백 구분 값과 카드의 `data-categories` 값을 비교한다.

## 이번 범위 밖

- 칩 클릭에 따른 카드 표시와 개수 갱신
- 수집 결과와 레포 카테고리의 결합 또는 저장
- 새 레포 등록 시 카테고리 입력 화면과 검증
- 이슈별 버그, 문서, 기능 같은 별도 이슈 유형 태그
- AI를 이용한 자동 분류

## 이후 구현 원칙

1. 필터는 카드의 `data-categories`를 기준으로 동작시키고, 카테고리별 건수는 그 데이터에서 계산한다.
2. 실제 수집을 연결할 때는 레포 등록 시 카테고리를 최대 두 개 선택해 레포 메타데이터로 보관한다. 이슈 수집마다 AI 분류를 실행하지 않는다.
3. 이슈 유형 필터가 필요해질 때만 별도 태그 축을 추가한다. 이 경우에도 기존 난이도 판정 요청의 구조화된 출력에 함께 넣고, 결과를 `repo + issue number` 기준으로 재사용한다.
