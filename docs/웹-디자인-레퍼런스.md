# RepoBite 웹 디자인 레퍼런스와 구현 계획

작성일: 2026-09-14

## 해결할 문제

현재 화면은 레포 설정과 실행 버튼이 왼쪽 전체를 차지하고, 결과는 상태 숫자와 동일한 카드 목록으로 이어진다. 기능은 찾기 쉽지만 사용자가 가장 먼저 봐야 할 추천 후보보다 운영 설정이 더 강하게 보인다.

개편의 목표는 후보 탐색을 화면 중심에 두고 설정과 실행 상태를 보조 영역으로 분리하는 것이다. 이번 단계에서는 기능을 연결하지 않고 정적 시안으로 정보 계층, 밀도, 색, 반응형 레이아웃만 비교한다.

## 확인한 레퍼런스

### [Layers Explore](https://layers.to/explore)

유일한 시각 원본이다. 2026-09-14 데스크톱 화면과 실제 HTML/CSS를 다시 확인했다. 왼쪽 아이콘 레일, 상단 필터, 중앙 masonry 피드, 오른쪽 보조 패널이 각자 한 역할만 맡는다.

가져갈 것:

- `72px / 유동 영역 / 360px`의 3단 구조
- 검은 배경, `InterVar` 계열 글꼴, zinc 계열 경계색
- 40px 높이의 둥근 필터와 흰색 선택 상태
- 3열 masonry 피드와 32px 간격
- 큰 미리보기 아래에 아바타, 작성자, 제목을 한 줄로 붙이는 카드
- 오른쪽 검색, 홍보 블록, 최근 목록의 수직 구성
- 모바일에서 레일과 오른쪽 패널을 숨기고 필터와 피드를 한 열로 만드는 방식

가져가지 않을 것:

- Layers 로고, 사용자 이미지, 게시물 이미지 같은 원본 자산
- Layers의 광고, 채용, 가입 콘텐츠와 문구
- 실제 동작하는 좋아요, 정렬, 검색, 로그인 기능
- 원본 서비스로 오인시킬 수 있는 이름과 브랜드 표식

### [Cosmos Explore](https://www.cosmos.so/explore)

가져갈 것:

- 검색을 전역 탐색의 중심에 두는 상단 구성
- 필터가 콘텐츠보다 무겁지 않은 가로 리듬
- 충분한 여백과 명확한 섹션 제목

가져가지 않을 것:

- 이미지가 있어야 성립하는 masonry 피드
- 화면 중앙을 크게 비우는 마케팅형 구성
- RepoBite 데이터와 관계없는 시각 유사도 탐색

### [The Pudding](https://pudding.cool)

가져갈 것:

- 콘텐츠 항목마다 핵심 정보가 다르게 보이는 강한 편집 계층
- 작은 분류 정보와 큰 제목의 분명한 대비
- 한 가지 기억점에만 힘을 주는 태도

가져가지 않을 것:

- 손그림 로고와 스티커 그래픽의 직접 모방
- 항목마다 다른 색을 써서 판정 의미가 흐려지는 구성
- 잡지형 이미지 썸네일

### [Are.na Explore](https://www.are.na/explore)

가져갈 것:

- 장식보다 여백, 선, 텍스트로 구조를 만드는 절제
- 필터 선택지를 그대로 드러내는 단순함
- 콘텐츠를 수집물처럼 다루는 태도

가져가지 않을 것:

- 정보량이 적을 때만 가능한 과도한 빈 공간
- 앱 상태와 판정 근거를 생략하는 극단적 최소화

### [Linear](https://linear.app)

가져갈 것:

- 레포, 번호, 상태, 제목, 설명 순서의 안정된 정보 계층
- 긴 텍스트가 있어도 흐트러지지 않는 행 기반 레이아웃
- 조용한 구분선과 제한된 색 사용

가져가지 않을 것:

- 제품 화면을 어둡고 흐리게 만드는 저채도 표현
- 작은 아이콘과 축약어에 과도하게 의존하는 밀도
- Linear 브랜드를 연상시키는 검은 화면 복제

### [Poolsuite](https://poolsuite.net)

가져갈 것은 제품 전체에 하나의 태도를 끝까지 유지하는 자신감뿐이다. 복고 데스크톱 창, 픽셀 그래픽, 색상은 RepoBite에 직접 사용하지 않는다.

## 선택한 방향

방향은 `Layers Explore for RepoBite`다. 새로운 대시보드 디자인을 만들지 않고 Layers Explore의 시각 문법을 최대한 그대로 사용한다. 중앙의 디자인 게시물만 RepoBite의 이슈 미리보기로 바꾼다.

이슈 카드는 코드 diff, 문서, 이슈 본문, 판정 체크리스트, 타입 검사, 테스트 결과를 정적인 미리보기로 보여준다. 모든 콘텐츠는 샘플임을 밝히며 실제 GitHub 이슈나 판정 결과로 오인시키지 않는다.

### 최소 차별화 원칙

Layers와 닮은 탐색 경험은 유지하되 원본 서비스로 오인될 만한 세 요소만 바꾼다.

- 겹친 사각형 로고 대신 레이더의 동심원과 탐침을 사용한다.
- 작성자 아바타 대신 후보의 `바로 착수`와 `확인 필요` 상태를 나타내는 신호를 사용한다.
- 오른쪽 최근 레포 목록 대신 판정 이벤트가 시간순으로 흐르는 `Radar stream`을 사용한다.

레일 폭, 필터 높이, masonry 열 수, 카드 간격, 오른쪽 패널 폭과 검은 색감은 유지한다. 차별화를 이유로 새로운 대시보드 구조나 장식 효과를 추가하지 않는다.

### 색

| 이름 | 값 | 역할 |
|---|---|---|
| Page | `oklch(14.1% 0.005 285.8)` | 전체 배경과 레일 |
| Raised | `oklch(21% 0.006 285.8)` | 검색창과 어두운 미리보기 |
| Rule | `oklch(27.4% 0.006 286)` | 레일과 오른쪽 패널 구분선 |
| Text | `oklch(96.7% 0.003 264.5)` | 주 텍스트와 활성 필터 |
| Muted | `oklch(62% 0.01 264)` | 제목 뒤 설명과 보조 정보 |
| Active | `oklch(98.5% 0 0)` | 선택된 필터와 밝은 미리보기 |

색은 미리보기 콘텐츠를 제외하면 무채색으로 제한한다.

### 글꼴

- 전체 UI: 원본이 선언한 `InterVar` 역할을 따라 `Inter`, Apple 시스템 글꼴, `Segoe UI` 순서로 사용한다.
- 코드 미리보기: `SFMono-Regular`, `Consolas`, `Liberation Mono`를 사용한다.
- 별도 display 글꼴이나 과장된 큰 제목은 만들지 않는다.

### 레이아웃

```text
+------+--------------------------------+------------------+
| 레일 | 추천순 / 가로 필터            | 이슈 검색        |
|      +--------------------------------+------------------+
|      | 3열 masonry 이슈 미리보기     | 소개 블록        |
|      | 이미지형 미리보기             |                  |
|      | 작성자 + 이슈 제목             | 최근 레포 목록   |
+------+--------------------------------+------------------+
```

- 데스크톱은 72px 레일, 유동 중앙 피드, 360px 오른쪽 패널을 사용한다.
- 중앙 피드는 3열 masonry이며 카드 사이 간격은 32px다.
- 1200px 아래에서는 오른쪽 패널을 숨기고, 900px 아래에서는 피드를 2열로 바꾼다.
- 768px 아래에서는 레일을 모바일 헤더로 바꾸고 피드를 한 열로 쌓는다.

## 가져가지 않을 AI 디자인 관습

- 큰 문구와 그라데이션으로 시작하는 hero
- 동일한 둥근 카드로 모든 정보를 분절하는 구성
- 의미 없는 4개 통계 카드
- 보라색 또는 파란색 광원 효과
- 장식용 영문 대문자 eyebrow
- 모든 항목에 그림자와 hover 이동을 붙이는 방식
- 제품과 무관한 추상 도형

첫 시안은 밝은 배경, 큰 제목, 색인 번호, 운영 장부를 사용해 결과적으로 전형적인 AI 대시보드처럼 보였다. 이 안은 폐기한다. 새 시안에는 별도 hero, 통계 카드, 색인 번호, 노란 강조색을 사용하지 않는다.

## 정적 시안 범위

`prototypes/layers.html`은 실제 데이터를 흉내 낸 독립 HTML이다.

포함:

- 데스크톱, 태블릿, 모바일 반응형 레이아웃
- 후보 3건의 실제와 유사한 샘플 콘텐츠
- 검색, 필터, 왼쪽 레일, 오른쪽 상태 패널의 시각 상태
- 키보드 초점과 충분한 색 대비

제외:

- API 요청
- JavaScript 상태 관리
- 수집과 판정 실행
- `candidates.jsonl` 연결
- 기존 `web.html` 변경

## 비교 기준

현재 화면과 정적 시안을 나란히 열고 다음을 확인한다.

1. 첫 3초 안에 추천 후보가 화면의 주인공으로 보이는가
2. 레포, 이슈 번호, 제목, 난이도를 순서대로 읽을 수 있는가 (판정 이유는 2026-10-23 화면 문구 규칙으로 노출하지 않음)
3. 설정과 실행 상태가 필요할 때 보이지만 후보 탐색을 방해하지 않는가
4. 후보가 0건, 3건, 50건일 때 같은 구조가 유지될 수 있는가
5. 390px 모바일 폭에서도 중요한 정보가 사라지지 않는가
6. Layers Explore와 나란히 놓았을 때 구조, 밀도, 카드 리듬이 같은 계열로 보이는가

## 승인 후 구현 계획

1. 정적 시안에서 레이아웃, 색, 밀도, 문구를 확정한다.
2. 기존 DOM의 기능용 ID와 이벤트 흐름을 보존한 채 `web.html`의 구조와 CSS만 옮긴다.
3. `test_web_ui.mjs`로 기존 수집, 제한 판정, 전체 판정, 필터 동작을 검증한다.
4. 데스크톱과 390px 화면을 캡처해 정적 시안과 비교한다.
5. 기능 연결은 별도 작업으로 남긴다. `candidates.jsonl` 보관함은 이 시각 개편에 포함하지 않는다.

## 구독·온보딩 시안 (2026-10-23)

정적 시안은 [design/subscription-redesign/index.html](../design/subscription-redesign/index.html) 한 파일에서 탐색 메인, 4단계 온보딩, 저장, 내 구독까지 이어서 체험하는 연결 프로토타입이다. 코덱스 `codex/subscription-proposals`의 TypeSafe 시안을 대체한다. 실제 `web.html`에는 아직 반영하지 않았다. 로컬 서버 없이 파일로 열어도 동작한다.

### 레퍼런스 역할

| 원본 | 가져온 것 | 가져오지 않은 것 |
|---|---|---|

| stoic (Figma `tn59Thk2GRcVLkzoO8k9Sr`, 노드 `1290:2882`) | 한 화면 한 질문, `‹ 진행 대시 ×` 상단, 원형 아이콘 선택 그리드, 알약 목록, 원형 다음 버튼, 스트릭 원, 토글 동의 | 밝은 배경, 새 일러스트, 영문 문구 |

### 화면과 실제 기능 대응

- 경로는 `#/explore`(첫 화면), `#/topics`, `#/repos`, `#/level`, `#/mail`, `#/subs`이고 브라우저 뒤로 가기에서도 선택이 유지된다. 저장은 화면 상태로만 흉내 내며 API를 호출하지 않는다.
- 실제 흐름(`codex/feature-integration`의 `subscription-pages.mjs`)은 저장소·난이도·알림 3단계다. 시안은 stoic식으로 관심 분야를 앞 단계로 분리한 4단계를 사용자 결정으로 유지한다(2026-10-23).
- 탐색 카드나 RECENT 행을 누르면 저장소 상세 다이얼로그가 열린다. 창 모달(A), 오른쪽 시트(B), 스펙 시트 오버레이(C) 세 시안 중 C로 확정했다(2026-10-23). 왼쪽에 큰 저장소 이름, 주인, 분야, 구독·GitHub 버튼을 두고, 오른쪽 스펙 시트에 대표 이미지, 이슈·분야 수, 난이도별 건수를, 아래에 난이도 칩과 이슈 2열 그리드를 둔다. 모바일은 전체 화면이다. 네이티브 `<dialog>`를 써서 Esc, ×, 바깥 클릭으로 닫힌다.
- 탐색 상단 주 버튼은 "레포바이트 이용하기"이며 흰 바탕 검은 글자로 반전한다(온보딩을 마친 뒤에는 "내 구독 보기").
- 레일의 탐색·내 구독 메뉴는 나침반과 책갈피를 20칸 격자로 그린 40px 아이콘이고, 아래에 `explore`, `my`를 픽셀 글씨로 적는다. 형태를 만드는 선은 2칸 이상 두께의 꽉 찬 실선, 안쪽만 점묘로 채우며 두 아이콘이 비슷한 면적을 차지하게 맞춘다. 현재 위치는 밝게(`--text`), 나머지는 `--muted`로 칠한다.
- 레일 왼쪽 위 서비스 아이콘은 어느 화면에서든 탐색 메인(`#/explore`)으로 이동한다. 아이콘은 알림 단계 삽화와 같은 꽃잎을 굵게 한 실루엣(`logo`)으로 확정했다(2026-10-23, 레이더·베어 문 구·블록 시안은 폐기). 메뉴 아이콘보다 크게 보이도록 같은 20칸 픽셀 패턴을 한 칸 3px, 60px로 정수배 확대한다. 모양은 사용자가 승인한 그대로 두고 크기만 바꾼다.
- 가로 스크롤은 쓰지 않는다. 탐색 분야 칩과 내 구독 모바일 저장소 칩은 첫 줄에 들어가는 만큼만 보이고 나머지는 `+N 더보기` 칩으로 접으며, 펼치면 줄바꿈으로 모두 보이고 끝에 "접기"가 붙는다. 선택된 칩은 접혀도 항상 보인다(2026-10-23 사용자 결정).
- "담기"나 정기 수집 대기 개념은 없다. 저장소는 사용자가 구독하는 순간 바로 수집한다(2026-10-23 사용자 결정).
- 탐색 메인은 "구독된 레포"(사용자들이 구독해 수집된 저장소)와 "POPULAR"(그 밖의 수집 저장소)를 따로 보여 준다. 시안에서는 glance, beszel, hister를 다른 사용자가 구독한 샘플로 두고, 내가 구독한 저장소도 구독된 레포에 올린다.
- RepoBite에 아직 없는 GitHub 저장소는 두 글자 이상 검색했을 때 탐색의 "GitHub에서 찾은 저장소"와 온보딩 저장소 목록에 나타난다. 시안에서는 bookorbit, zmx를 이런 샘플로 숨겨 두었다. 상세 다이얼로그와 목록에 "구독하면 바로 수집" 안내를 두고, 구독하면 진행 토스트(이슈 가져오기, 난이도 판정, 정리)를 띄운 뒤 완료 토스트로 바꾸며 구독된 레포로 옮긴다. 토스트는 `popover`로 열어 상세 다이얼로그 위에도 보이게 한다. 시안의 수집은 약 4~6초 진행 후 숨겨 둔 샘플 이슈를 보여 주는 흉내이며, 실제 백엔드 즉시 수집은 구현하지 않았다.
- 오른쪽 패널은 검색과 RECENT만 둔다. 오른쪽 패널이 숨는 1200px 아래에서는 오른쪽 위(태블릿은 탐색 화면 위, 모바일은 상단 바 끝)에 돋보기 버튼을 두고, 누르면 필터 바 위에 검색칸을 펼친다. 닫으면 검색어를 비운다.
- 검색 입력 중에는 결과 목록만 다시 그리고 입력칸 요소는 바꿔 끼우지 않는다. 입력칸을 다시 만들면 한글 자모 조합이 끊겨 "ㅇㅏㄴ"처럼 흩어진다. 고른 저장소의 이슈는 상세 다이얼로그에서 본다.
- 온보딩 전 사용자가 상세 다이얼로그에서 구독하면 페이지를 옮기지 않고 같은 자리에서 온보딩 다이얼로그를 연다. 저장소가 이미 정해졌으므로 분야·저장소 단계는 없고, 전체 화면 온보딩의 난이도와 알림 화면만 1·2단계(`STEP 01 / 02`)로 쓴다. 1단계 왼쪽 아래 링크는 "나중에 할게요"(닫기)다. 마치면 다이얼로그를 닫고 탐색에 머문 채 "구독을 시작했습니다" 토스트와 "내 구독" 버튼을 보여 준다. 온보딩을 마친 뒤에는 상세에서 바로 구독 목록에 추가한다. "레포바이트 이용하기"는 전체 화면 온보딩으로 들어간다.
- 경험 3단계와 경험별 Lv 추천, 하루 최대 3개 문구, 수신 동의 없이 알림받기 불가 규칙은 실제 화면 값을 따른다. 샘플은 `data.json`(2026-09-16 스냅숏)에서 오류·제외 이슈를 뺀 50건을 [data.js](../design/subscription-redesign/data.js)로 추렸다.

### 규칙

- 한글에는 Pretendard를 쓰고 픽셀 글꼴(VT323)은 한글이 없는 라벨(창 제목, 숫자, 영문 메타)에만 쓴다. 한글 라벨을 VT323으로 지정하면 대체 글꼴로 크기가 들쭉날쭉해진다.
- 난이도는 `Lv.1 쉬움 / Lv.2 보통 / Lv.3 어려움`으로만 표시한다. 본문 충분도로 난이도를 설명하는 문장, 판정 이유, READINESS 값은 보여 주지 않으며 `data.js`에도 싣지 않는다(AGENTS.md 화면 문구 규칙).
- 창, 눈금, 원 격자, 스펙 시트의 값은 모두 선택 상태와 샘플 데이터에서 계산한다. 시계 같은 장식 위젯은 두지 않는다.
- 저장소 이미지는 탐색 카드, 온보딩 저장소 목록(썸네일), 난이도 단계 스펙 시트에서 메인과 같이 원본을 보여 준다. README 대표 이미지 > GitHub 소셜 미리보기 > 저장소 이름 순으로 대체하고(`repoMedia`), 탐색 카드와 RECENT 행에는 저장소 주인 아바타를 둔다. 디더 그림은 바탕 점묘, 단계 삽화, 내 구독 아바타처럼 RepoBite가 직접 그리는 자리에만 쓴다.
- 이슈 수는 `1 issue`, `2 issues`처럼 쓴다. `ISS` 같은 축약은 쓰지 않는다.
- 알림 단계에 수동 발송 안내 문장은 두지 않는다(2026-10-23 사용자 결정).
- 데스크톱 점묘는 가장자리 언덕으로만 두고 본문 라벨과 겹치지 않게 한다.
- 내 구독의 저장소 아바타는 저장소 이름을 시드로 만든 디더 그림이다(`dither.js`).
- 확인 조건: 1440×900 데스크톱, 390×844 모바일(오른쪽 패널 숨김, 레일은 상단 바), 두 폭에서 가로 스크롤 없음.

### 수집 범위 밖의 저장소 검색 (2026-10-23 사용자 수정)

- 메인의 오른쪽 검색과 좁은 화면의 펼침 검색은 RepoBite가 수집한 저장소 이름·설명만 검색한다. 입력만으로 GitHub API를 호출하지 않는다. 위 시안의 메인 자동 GitHub 검색 규칙은 이 결정으로 대체한다.
- 검색 결과가 없으면 중앙에 "찾으시는 레포지토리가 없나요?" 안내와 "GitHub에서 레포지토리 찾기" 버튼을 보여 준다. 누르면 메인 검색어를 가져온 별도 검색 대화상자가 열린다. 오른쪽 패널의 "GitHub에서 다른 저장소 찾기"로도 열 수 있다.
- 대화상자는 현행 `repobite.css`의 zinc 다크 토큰, 반전 타이틀바, 입력창과 흰색 버튼을 쓴다. `web.html`의 네이티브 `dialog`와 `repository-search-dialog.mjs`가 대화상자 입력·요청·닫기를 담당한다. 기존 `web.Application`의 단일 책임 원칙 위반은 운영 문서에 기록되어 있으며, 이번 검색 책임은 이 클래스에 추가하지 않는다.
- GitHub의 활성 공개 저장소를 두 글자 이상으로 검색한다. 한글 조합 중 요청하지 않으며 로딩, 결과 없음과 검색 제한 오류를 구분한다. 입력창을 다시 만들지 않고 늦게 온 이전 응답은 무시한다. Esc·닫기·바깥 클릭으로 닫으면 진행 중 검색을 취소한다.
- 결과를 선택하면 검색창을 닫고 기존 저장소 상세를 연다. 검색과 선택만으로 구독하지 않는다. 상세의 구독 버튼에서 기존 로그인·온보딩·즉시 수집 흐름을 사용한다.
- 온보딩의 저장소 검색은 기존대로 GitHub 검색을 지원한다. 메인 검색의 범위와 대화상자의 범위는 서로 다르다.
