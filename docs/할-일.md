# RepoBite 할 일

착수 전 항목이다. 착수할 때 사용자에게 범위를 확인하고, 끝나면 이 목록에서 지운 뒤 결과 문서를 링크한다.

## Jev로 분류 작업 전환 검토 (2026-10-26 등록)

### 배경

- 공개 화면은 판정이 없는 이슈를 숨긴다. 정기 수집은 최근 24시간 갱신 이슈 1,400~1,700건을 가져오지만 판정은 실행당 100건, 레포당 20건이 상한이라 대부분의 이슈가 화면에 나오지 않는다.
- Vertex AI의 `429 RESOURCE_EXHAUSTED`는 크레딧 부족이 아니라 공용 처리 용량이 바쁠 때 생기는 일시 오류로 본다(사용자 관찰).
- 판정 결과는 모두 분류다: 난이도 1~3(점수), 준비도(단일 라벨), 제외 여부(예/아니오). 화면·메일은 `grade.reason`을 보여 주지 않는다.
- [Jev](https://typesafe.ai)는 TypeSafe AI의 비생성형 분류 모델이다. 질문과 라벨을 요청 시점에 지정하면 범주·점수·확률을 반환한다. 2026-09 말 신규 가입 중단 보도가 있어 계정 사용 가능 여부를 먼저 확인한다.

### 순서

1. 접근 확인: 계정·API 키 발급 가능 여부, 요금, 요청 한도, 입력 데이터 보관 정책.
2. 비교 실측: 기존 기준 표본을 Jev로 판정하고 현행 Gemini 판정, 사람 판정과 비교한다.
   - 기준: [현행 v2 무작위 30건 반복 실측](현행-v2-무작위30-반복실측.md), [현행 v2 품질 검증](현행-v2-품질-검증.md), `fixtures/sample30.json`.
   - 지표: 추천 여부(Lv.1 · 바로 착수 · 비제외) 일치율, 축별 일치율, 같은 입력 반복 일치율, 건당 지연 시간과 비용.
   - 기존 실측 문서는 덮어쓰지 않고 새 문서로 기록한다.
3. 비교 결과가 현행 이상이면 정기 배치(`community_batch.py`)의 이슈 판정을 Jev로 바꾸고 실행당 상한을 해제한다. 실패 건은 지금처럼 다음 회차에 다시 판정한다.
4. 저장소 분야 분류(`codex/repository-categorization`)도 같은 방식으로 비교한 뒤 전환한다. 정해진 분야 목록에서 여러 개를 고르는 작업이라 이슈 판정보다 적합도가 높다.

### 함께 결정할 것

- `grade.reason`이 사라진다. 화면에는 영향이 없지만 오판 조사와 품질 감사에 써 왔다. 오판 조사용으로만 LLM 이유 생성을 남길지 정한다.
- 판정 기준 버전(`criteria_version`)과 모델 이름이 바뀌면 기존 판정 재사용이 끊긴다. 전환 직후 한 회차의 판정량을 감안한다.
- 전환 전까지 이슈 노출 부족은 남는다. 그동안 Vertex로 상한만 먼저 올릴지 정한다.
