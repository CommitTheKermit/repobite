# RepoBite 할 일

착수 전 항목이다. 착수할 때 사용자에게 범위를 확인하고, 끝나면 이 목록에서 지운 뒤 결과 문서를 링크한다.

## Jev로 분류 작업 전환 검토 (2026-10-26 등록)

### 배경

- 공개 화면은 판정이 없는 이슈를 숨긴다. 정기 수집은 최근 24시간 갱신 이슈 1,400~1,700건을 가져오지만 판정은 실행당 100건, 레포당 20건이 상한이라 대부분의 이슈가 화면에 나오지 않는다.
- Vertex AI의 `429 RESOURCE_EXHAUSTED`는 크레딧 부족이 아니라 공용 처리 용량이 바쁠 때 생기는 일시 오류로 본다(사용자 관찰).
- 판정 결과는 모두 분류다: 난이도 1~3(점수), 준비도(단일 라벨), 제외 여부(예/아니오). 화면·메일은 `grade.reason`을 보여 주지 않는다.
- [Jev](https://typesafe.ai)는 TypeSafe AI의 비생성형 분류 모델이다. 질문과 라벨을 요청 시점에 지정하면 범주·점수·확률을 반환한다. 2026-09 말 신규 가입 중단 보도가 있어 계정 사용 가능 여부를 먼저 확인한다.

### 순서

1. 접근 확인: 계정·API 키 발급 가능 여부, 요금, 요청 한도, 입력 데이터 보관 정책.
2. 비교 실측: 기존 기준 표본을 Jev로 판정하고 현행 Gemini 판정, 사람 판정과 비교한다.
   - 기준: [현행 v2 무작위 30건 반복 실측](현행-v2-무작위30-반복실측.md), [현행 v2 품질 검증](현행-v2-품질-검증.md), `fixtures/sample30.json`.
   - 지표: 추천 여부(Lv.1 · 바로 착수 · 비제외) 일치율, 축별 일치율, 같은 입력 반복 일치율, 건당 지연 시간과 비용.
   - 기존 실측 문서는 덮어쓰지 않고 새 문서로 기록한다.
3. 비교 결과가 현행 이상이면 정기 배치(`community_batch.py`)의 이슈 판정을 Jev로 바꾸고 실행당 상한을 해제한다. 실패 건은 지금처럼 다음 회차에 다시 판정한다.
4. 저장소 분야 분류(`codex/repository-categorization`)도 같은 방식으로 비교한 뒤 전환한다. 정해진 분야 목록에서 여러 개를 고르는 작업이라 이슈 판정보다 적합도가 높다.

### 함께 결정할 것

- `grade.reason`이 사라진다. 화면에는 영향이 없지만 오판 조사와 품질 감사에 써 왔다. 오판 조사용으로만 LLM 이유 생성을 남길지 정한다.
- 판정 기준 버전(`criteria_version`)과 모델 이름이 바뀌면 기존 판정 재사용이 끊긴다. 전환 직후 한 회차의 판정량을 감안한다.
- 전환 전까지 이슈 노출 부족은 남는다. 그동안 Vertex로 상한만 먼저 올릴지 정한다.

## 저장소 AI 기여 정책 반영 (2026-10-26 등록)

### 배경

- RepoBite의 의도한 흐름은 "구조화된 이슈 → 사용자가 AI로 해결 → PR"이다.
- [AI 기여 정책 조사](저장소-AI-기여정책-조사.md)에서 이 흐름을 막는 저장소를 확인했다.
  - 외부 PR 불가 또는 사전 승인 필수: hono, pocketbase, ghostty(vouch 승인), bookorbit(승인·배정)
  - AI 사용 강한 제한: mlx(에이전트의 PR 생성·push·리뷰 답변 시 차단), hister(good first issue에 AI 금지)
  - AI 사용 공개 필수: ghostty, hister, bookorbit, OpenMAIC, OpenViking, archify
- 조사는 2026-10-23 스냅샷 기준 57개 중 38개만 확인했다. 정책은 바뀐다(pocketbase는 "일시 중단").

### 순서

1. 판별 규칙 확정: 저장소의 `AI_POLICY*`, CONTRIBUTING의 AI 정책 절, PR 템플릿의 사람 참여 항목, "PR은 메인테이너만", "vouch", "승인·배정 후 PR" 문구에서 정책을 아래 단계로 분류한다.
   - `blocked`: 외부 PR 불가, 또는 AI 기여 금지
   - `approval`: PR 전 승인·배정·vouch 필요
   - `disclose`: AI 사용 공개 필수
   - `allowed`: 허용 또는 명시 정책 없음
2. 정기 수집에 정책 확인을 넣고 결과를 저장소 메타데이터로 저장한다. 문서가 바뀌지 않았으면 이전 결과를 재사용한다. 분류 작업이므로 위 Jev 검토와 같이 진행할 수 있다.
3. `blocked` 저장소의 이슈는 추천·이메일에서 제외한다. `approval`과 `disclose`는 저장소 상세와 이슈 옆에 짧게 표시한다(예: `PR 전 승인 필요`, `AI 사용 공개 필요`). 원문 정책 링크를 함께 둔다.
4. 미확인 19개를 포함해 수집 저장소 전체에 적용하고, 조사 문서를 결과로 갱신한다.

### 함께 결정할 것

- `blocked` 저장소를 수집 목록에서 아예 뺄지, 화면에는 두고 추천만 막을지.
- 개인 구독한 저장소가 `blocked`일 때 구독을 유지하고 안내만 할지.
- 자동 발굴에 섞인 큐레이션 목록 저장소(awesome, public-apis, 로드맵·면접 자료 등)를 발굴 기준에서 뺄지. 정책과 별개로 "이슈를 코드로 푸는" 흐름에 맞지 않는다.

## 이슈별 AI 작업 지시서 복사 버튼 (2026-10-26 등록)

### 배경

- 사용자가 이슈를 AI 에이전트(Claude Code, Codex, Cursor 등)에 넘길 때 바로 붙여 넣을 작업 지시서가 있으면 흐름이 끊기지 않는다.
- 위치: 저장소 상세의 이슈 목록에서 각 이슈 옆, 그리고 이슈를 열었을 때의 상세.

### 지시서에 담을 내용

- 대상: 저장소, 이슈 번호·제목·URL. 에이전트가 이슈 본문과 댓글을 직접 읽게 한다.
- 시작 전 확인: 이슈가 열려 있는지, 담당자와 연결된 열린 PR이 없는지, 이슈에 작업 의사를 댓글로 남길지 사용자에게 묻기.
- 저장소 규칙: CONTRIBUTING·AGENTS.md를 먼저 읽고 따르게 한다. 위 AI 정책 반영 결과가 있으면 해당 저장소의 규칙을 넣는다(예: AI 사용 공개 형식, PR 전 승인 필요).
- 작업 범위: 재현 → 최소 수정 → 테스트 추가·실행 → 사람이 이해할 수 있게 변경 요약.
- 금지: 에이전트가 사용자 대신 push, PR 생성, 리뷰 답변을 하지 않는다. PR 설명은 사용자가 자기 말로 쓰도록 초안만 준다. mlx 같은 저장소는 이를 어기면 차단한다.

### 제약

- 화면 문구 규칙(`AGENTS.md`)에 따라 `grade.reason`과 `readiness`, 본문 충분도 설명을 지시서에 넣지 않는다. 지시서도 화면에 노출되는 문구다.
- `blocked` 저장소에서는 버튼을 숨기거나 막고 이유를 표시한다. AI 정책 반영 작업이 먼저 끝나야 이 동작을 넣을 수 있다.
- 복사는 `navigator.clipboard`를 쓰고, 실패하면 지시서를 선택 가능한 글상자로 보여 준다. 복사 성공·실패를 짧게 알린다.
- 반응 측정에 복사 횟수 이벤트(예: `prompt_copy`)를 추가해 실제 사용 여부를 본다. 허용 이벤트 목록과 README의 반응 측정 절을 함께 고친다.

### 함께 결정할 것

- 지시서를 한국어로 쓸지 영어로 쓸지(에이전트 성능과 사용자 가독성).
- 특정 에이전트용 형식(예: Claude Code 슬래시 명령)을 둘지, 공통 형식 하나만 둘지.
