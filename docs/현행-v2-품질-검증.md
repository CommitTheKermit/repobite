확인일: 2026-10-21. 현행 프로필은 `gemini-3.1-flash-lite`, `minimal`, `criteria_version=2`다.
v2 의미는 [기획서 20절](기획서.md)을 따른다. 과거의 독립된 난이도/준비도 실측과 구분한다.

새 평가 도구로 읽은 결과다. SSH 연결과 집계만 실행했으며 Vertex/GitHub 호출은 하지 않았다.
공개 문서에는 이슈 원문, 개인 호스트/경로와 인증값을 복사하지 않았다.

115건을 최근 실행의 신규 호출 수로 해석하지 않는다. 수집 제외/상한 미선택까지 포함한 일반 모집단도 아니다.
저장된 freshness는 당시 스냅샷이며 현재 이슈가 여전히 추천 가능하다는 증거가 아니다.
반복 판정 입력과 새로운 사람 감사가 없어 반복 안정성, 정밀도와 재현율은 측정하지 못했다.

## 평가 도구

`quality_measurement.py`는 판정 JSONL을 오프라인 집계한다. 프로필이 다르거나 미확인인 행은
현행 분모/분자에서 제외하고 별도 건수로 남긴다. 분모는 해당 프로필의 성공·실패 전체 행이며
모델 호출 수가 아니다. 원시 후보와 freshness 통과 후보를 구분하고 최신성 미확인은 partial로 표시한다.

```sh
python3.14 quality_measurement.py --input current-grades.jsonl --scope sample --scope-description "수집 시점과 선정 방법" --output quality-v2.json
```

`--repeat`은 다른 실행의 판정 파일을 받는다. 같은 제목/본문/프로필의 성공 공통키만 비교하며
등급, 준비도, 제외, 세 필드 동시 일치, 원시 추천 여부 일치를 기록한다.
반복 입력이 없으면 측정 불가다. 원시 추천 일치는 최신성 변화나 사람 판정의 정확도가 아니다.

`--audit`은 기존 `{repo,number,verdict,reason}` JSON 배열을 받는다.
감사 범위의 plausible/conditional/incorrect를 사용하며 본문이 없으면 동일성 미확인을 명시한다.
기본 `--audit-scope selected`는 전체 재현율을 추정하지 않는다.
`all-input`도 전체 감사가 완결되고 실패가 없으며 비추천 이슈까지 감사한 경우에만 감사 범위의 재현율을 산출한다.
후보 양성만 감사한 경우 누락과 재현율은 측정 불가다. 원본 입력 경로를 출력으로 덮어쓰지 못한다.

## 남은 현행 품질 실측

사용자가 승인한 새 판정 최대 60건으로 [고정 무작위 30건의 독립 반복 실측](현행-v2-무작위30-반복실측.md)을 수행했다.
실제 60건이 모두 성공하고 세 필드가 30/30 일치했다. 위 누적 집계와 별개이며 기본 30개 저장소 표본을 GitHub 전체로 일반화하지 않는다.
사람이 수행한 감사와 정확도·정밀도·재현율 검증은 남아 있다.
과거 [일반 모집단 실측](일반-모집단-품질-실측.md), [Gemini 표본](Gemini-표본30-실측.md)과 감사 원본은 보존한다.
