# 홈서버 내부 상태 페이지

상태 조회는 RepoBite 웹 프로세스에서 별도 loopback 포트 `8767`로 제공한다.
`/status`는 사람용 화면, `/status.json`은 세션 간 상태 확인용 JSON이다.
이 포트에는 RepoBite 관리 API나 파일 다운로드 기능이 없다.
공개 Vercel 배포 대상에도 포함하지 않는다.

## 연결

Windows의 사용자 환경변수 `HOME_STATUS_HOST`에 Tailscale HTTPS 호스트와 포트를 등록한다.
실제 값은 저장소 밖에서 관리한다. `scripts/run-web.ps1`은 시작할 때 이 값을 읽는다.
상태 서버는 `127.0.0.1:8767`에만 연결하고 Tailscale Serve를 통해 내부 HTTPS로 제공한다.
기존 Serve 설정을 먼저 확인하고 사용하지 않는 HTTPS 포트를 선택한다. 현재 구성은 `8443`이다.

```powershell
tailscale serve --bg --https=8443 http://127.0.0.1:8767
tailscale serve status --json
```

Funnel은 켜지 않는다. 기존 443 서비스 설정은 유지한다.
클라이언트와 서버가 같은 tailnet에 연결되어 있고 ACL이 허용해야 접속할 수 있다.
실제 주소는 Git 밖의 `~/.config/home-server/status-url`에 저장한다.

## 상태 의미

- PowerShell은 서비스 이름·실행 상태·시작 유형, 예약 작업의 최근 결과·실행 시각,
  다음 예약 시각, 부팅 시각과 RepoBite HTTP 응답만 반환한다.
- 계정·경로·명령 인자·환경변수·원본 오류·인증값은 반환하지 않는다.
- Tailscale 서비스 실행 상태는 표시하지만 다른 장치에서의 네트워크 도달성을 보장하지 않는다.
- 결과는 30초 동안 캐시하며 모든 응답에 `Cache-Control: no-store`를 적용한다.
  수집 실패는 확인 불가로 바꾼다. 이전 성공을 새 성공으로 표시하지 않는다.
- 로컬과 공용 수집 파일의 행 수·갱신 시각을 분리한다. 36시간 경과는 오래됨으로 표시한다.
  행 수는 파일 현황이며 데이터 품질이나 공용 DB 연결 성공의 증거는 아니다.
- 운영 메모는 저장소 루트의 `.home-status-notes.json` 문자열 배열로 관리한다.
  Git에서 제외되며 최대 10개, 항목당 500자를 표시한다. 공개 가능한 사건 요약만 쓰고
  비밀값·서버 식별자·개인 경로는 넣지 않는다. 화면에는 텍스트로만 표시한다.

## 운영과 검증

서버나 네트워크가 중단되면 상태 페이지도 중단된다. 독립 복구 경로로 취급하지 않는다.
연결 실패 시 화면의 과거 상태를 현재 정상 상태로 판단하지 않는다.
재부팅은 현장 대응 또는 독립된 콘솔이 확보된 뒤에만 수행한다.

```sh
python3 test_home_status.py
python3 test_web.py
```

Windows에서는 `test_windows.ps1`로 래퍼와 수집 스크립트 문법도 검증한다.
실제 배포 후 내부 HTTPS의 HTML/JSON 응답, 서비스 조회 성공, 임의 Host 차단,
`/api/run` 차단과 Funnel 비활성화를 확인한다.
