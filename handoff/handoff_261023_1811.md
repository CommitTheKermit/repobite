## 무엇을 만드는가

확정된 시안을 운영 화면(Vercel `https://repobite.vercel.app`)에 옮기고, 시안에서 흉내만 낸 "구독하면 바로 수집" 기능을 실제로 구현한다. 핵심 변화는 세 가지다.

1. 화면 개편: 탐색 메인, 저장소 상세 다이얼로그, 4단계 온보딩, 상세에서 여는 2단계 온보딩 다이얼로그, 내 구독.
2. 제품 구조 변경: "레포 담기"와 정기 수집 대기 개념을 없애고, 저장소는 누군가 구독하는 순간 수집한다.
3. 표시 규칙 변경: 난이도를 `쉬움/보통/어려움`으로만 보여 주고 판정 이유와 준비 상태를 노출하지 않는다(화면과 메일 모두).

## 이번 작업에서 확정한 결정

모두 2026-10-23 사용자 결정이다.

- 화면 문구: 난이도는 `Lv.1 쉬움 / Lv.2 보통 / Lv.3 어려움`만 쓴다. `본문 충분/추가 정보 필요/판단 보류`, "본문 정보가 충분해 쉽다" 같은 설명, `grade.reason`, `readiness`는 화면·이메일·안내문에 노출하지 않는다. 판정 기준과 저장 값은 바꾸지 않는다.
- 제품 구조: "레포 담기(+)"와 "다음 정기 수집 때 가져온다"는 개념을 쓰지 않는다. 저장소는 구독하는 순간 바로 수집한다. 탐색은 "구독된 레포"(다른 사용자가 구독한 저장소, 안내 문구 그대로 "다른 사용자가 구독한 저장소입니다.")와 "POPULAR"(그 밖의 수집 저장소)로 나눈다.
- 수집 전 상태는 RepoBite에 아직 없는 GitHub 저장소를 검색해 처음 구독할 때만 생긴다. 검색 결과에 "RepoBite에 아직 없음 · 구독하면 바로 수집" 안내를 둔다.
- 구독 즉시 수집의 진행은 토스트로 보이고, 끝나면 완료 토스트로 바꾼다.
- 탐색 메인: 메인 레이아웃(레일 / 정렬·분야 칩 / 3열 masonry / 360px 오른쪽 패널)은 유지하고 카드를 TypeSafe 창으로 감싼다. 저장소 이미지는 원본을 쓴다(README 대표 이미지 > GitHub 소셜 미리보기 > 저장소 이름). 카드와 RECENT 행에 저장소 주인 아바타를 둔다. 상단 주 버튼은 "레포바이트 이용하기"(흰 바탕 반전).
- 저장소 상세: 카드나 RECENT 행을 누르면 스펙 시트형 오버레이 다이얼로그(시안 C)가 열린다. 오른쪽 패널은 검색과 RECENT만 둔다.
- 온보딩: 전체 화면은 분야 → 저장소 → 난이도 → 알림 4단계(stoic 구성). 온보딩 전 사용자가 상세에서 구독하면 페이지를 옮기지 않고 난이도·알림 2단계 다이얼로그(`STEP 01 / 02`)를 연다.
- 가로 스크롤 금지: 칩은 첫 줄만 보이고 `+N 더보기`로 접는다.
- 1200px 아래에서는 오른쪽 위 돋보기 버튼(모바일은 상단 바 끝)으로 검색칸을 펼친다.
- 레일: 서비스 로고는 굵은 꽃잎 실루엣(`logo`, 20칸 패턴을 60px로 정수배), 메뉴는 디더 나침반·책갈피(20칸 40px)와 `explore`, `my` 라벨. 로고는 어디서든 탐색으로 이동한다.
- 시계·Game of Life 위젯은 넣지 않는다. 알림 단계의 "운영자가 확인한 뒤 수동으로 발송합니다" 문장은 지운다.

## 즉시 수집 설계안 (확정 전 초안)

- 요청: 구독 저장(`action=subscriptions` POST) 성공 시, 그 저장소가 현재 snapshot에 없으면 Upstash에 수집 요청을 넣는다(예: 목록 `repobite:collect:queue`, 저장소별 상태 `repobite:collect:<repo>`). 이미 수집된 저장소는 요청하지 않는다.
- 실행: Vercel 함수는 수 분 걸리는 수집·판정을 맡을 수 없으므로 Windows 홈서버 작업자가 큐를 짧은 주기로 확인해 한 저장소씩 처리한다. 기존 `radar.py` 수집·판정과 레포당 20건 상한을 재사용하고 동시 판정은 1~4로 낮게 둔다.
- 병합: 결과를 `repobite:snapshot`에 저장소 단위로 병합한다. 매일 03:00 배치가 snapshot 전체를 교체하므로 배치 실행 중에는 작업자가 쓰지 않도록 Redis 잠금을 두고, 배치는 시작 시점 이후 병합된 저장소를 잃지 않게 한다.
- 상태: 화면은 상태 조회 API를 주기적으로 읽어 토스트를 바꾼다. 실제 단계(대기 / 이슈 가져오기 / 판정 / 완료 / 실패)로 표시하고, 시안의 퍼센트처럼 지어낸 진행률은 쓰지 않는다. 실패(429, GitHub 오류)는 실패 토스트와 다음 정기 배치 재시도로 처리한다.
- 공개 범위: "구독된 레포" 표시를 위해 공개 피드에는 구독 저장소 이름만 넣고 사용자 식별자나 이메일은 넣지 않는다.

## 미결정 (구현 전에 사용자 확인)

- 기존 공용 등록(`repobite:repos`) 데이터를 구독으로 옮길지 버릴지.
- 즉시 수집 작업자의 형태(상시 실행 루프 / 짧은 주기 예약 작업)와 확인 주기, 동시 처리 수.
- 즉시 수집 실패 시 사용자 안내와 재시도 정책.
- "구독된 레포"에 구독자 수를 보여 줄지. 내 구독 저장소도 이 구역에 올릴지(시안은 올림).
- 레일 디더 아이콘과 TypeSafe 질감을 홈서버 화면(`web.py`)에도 같게 적용할지, Vercel 화면에만 적용할지.

## 제약 / 함정

- 시안의 `OTHERS`(다른 사용자 구독 샘플), `GITHUB`(미수집 샘플), 수집 진행 퍼센트와 4~6초 지연은 모두 흉내다. 운영 코드로 옮기지 않는다.
- 검색 입력 중에는 결과 영역만 다시 그리고 입력칸 요소를 교체하지 않는다. 교체하면 한글 조합이 끊긴다(시안에서 실제로 발생 후 수정).
- `<dialog>`의 close 이벤트는 비동기다. 닫은 직후 다시 그리면 다이얼로그가 도로 열리므로 닫을 때 상태를 먼저 비운다.
- 토스트는 `popover="manual"`로 띄워 모달 다이얼로그 위에 보이게 한다. 새 다이얼로그를 연 직후 토스트를 다시 열어야 위로 올라온다.
- 레일 링크 공통 크기 규칙(`.rail a` 40px)이 로고에 걸리면 가운데 정렬이 틀어진다.
- 작은 아이콘은 디더 점묘만으로는 흐려진다. 형태 선은 꽉 찬 실선, 안쪽만 점묘로 채운다.
- `.vercelignore`는 허용 목록 방식이라 새 JS·CSS·글꼴을 추가하지 않으면 운영에서 404가 난다.
- 홈서버 `web.py` CSP는 외부 CDN을 막는다. 글꼴과 스크립트는 자체 호스팅한다.
- Vertex 429가 정기 배치에서도 발생한 이력이 있다. 즉시 수집이 정기 배치와 같은 할당량을 쓰므로 동시성을 낮게 시작한다.
- `web.Application`의 상태·프로세스·파일 저장 책임 혼합(단일 책임 원칙 위반)은 여전히 남아 있다. 이번 작업 범위에서 넓히지 않는다.
- 비밀값(OAuth, Upstash, 서비스 계정)은 채팅·소스·명령 인자·문서에 쓰지 않는다.
